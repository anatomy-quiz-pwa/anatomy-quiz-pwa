# bestseller — 把素材變成一本書

## 整體流程

六個階段，每個階段結束都「停下來」等使用者審核才繼續。
不要連續執行多個階段。

```
Stage 1 素材盤點   → 產出 manifest.md（素材清單 + 標籤）
Stage 2 主題地圖   → 產出 themes.md（主題群 + 每群素材）
Stage 3 章節大綱   → 產出 outline.md（書名 + 章節結構）
Stage 4 逐章寫稿   → 產出 chapters/01-xxx.md ... NN-xxx.md
Stage 5 整書潤飾   → 產出 book.md（全書合一 + 序 + 結語）
Stage 6 PDF 輸出   → 用 pdf skill 產出最終 .pdf
```

## 全書設定檔（book-config.yaml）

開始 Stage 1 之前，先建立 book-config.yaml，所有後續階段都要讀它：

```yaml
title: "（待定，Stage 3 後填入）"
subtitle: ""
author: "Paopao（What's Up Anatomy）"
audience: "（誰會讀這本書？例如：解剖學學員 / 新手爸媽 / 同行老師）"
tone: "（語氣：學術嚴謹 / 親切口語 / 教學手冊）"
language: "Traditional Chinese (Taiwan)"
terminology: "台灣醫學術語"
length_target: "150–200 頁"
forbidden_phrases:
  - "在這個快速變化的時代"
  - "綜上所述"
  - "讓我們一起"
style_anchors:
  - "用具體案例帶觀念，不要先講抽象理論"
  - "每章開頭一個故事，結尾一個 take-home message"
  - "圖表用文字描述，標註 [圖：xxx] 待後製"
```

這份設定是寫稿一致性的關鍵。沒有它，每章語氣會飄。

## Stage 1：素材盤點（manifest.md）

**輸入**：使用者指定的素材資料夾路徑（可包含 .md / .txt / .docx / .pdf / .json）

**動作**：

1. 掃描資料夾，列出所有檔案
2. 對每個檔案產出一行：檔名 | 字數 | 類型 | 一句話摘要 | 候選標籤
3. 類型分類：逐字稿 / 貼文 / 文獻卡片 / 教學筆記 / Prompt / 心得 / 對話記錄 / 其他
4. 候選標籤：先粗抓 5–10 個高頻主題標籤（例如：呼吸、骨盆、教學心法、學員 Q&A）

**輸出格式（manifest.md）**：

```markdown
# 素材盤點

總計：N 個檔案 / 約 X 萬字

## 標籤統計
- 呼吸：12 篇
- 骨盆：8 篇
- ...

## 檔案清單
| 檔名 | 字數 | 類型 | 摘要 | 標籤 |
| --- | --- | --- | --- | --- |
| 2024-03-15-呼吸營逐字稿.md | 8200 | 逐字稿 | 第一堂課介紹橫膈膜... | 呼吸,教學心法 |
| ... | | | | |
```

**Stage 1 結束 → 停下來。** 對使用者說：

> 「素材盤點完成，請審核 manifest.md。確認標籤分類合理後，我再進入 Stage 2 主題地圖。」

---

## Stage 2：主題地圖（themes.md）

**輸入**：審核過的 manifest.md

**動作**：

1. 把標籤聚合成 5–10 個「主題群」（這些將是書的章節候選）
2. 每個主題群列出：
   - 主題名稱
   - 對應的素材檔案（從 manifest 抓）
   - 該主題的核心觀點 3–5 條（從素材中萃取）
   - 缺口：哪些子主題素材不夠，可能要補寫

**輸出格式**：

```markdown
# 主題地圖

## 主題 1：呼吸與軀幹穩定
**素材**：
- 2024-03-15-呼吸營逐字稿.md
- 2024-04-02-FB-橫膈膜貼文.md
- ...

**核心觀點**：
1. 呼吸不只是換氣，是軀幹的張力調節器
2. ...

**缺口**：
- 沒有「呼吸與情緒」的素材，但讀者可能會想看
```

**Stage 2 結束 → 停下來。** 對使用者說：

> 「主題地圖完成。請決定：(a) 哪些主題要保留 / 合併 / 拆開 (b) 缺口要補寫還是直接捨棄。」

---

## Stage 3：章節大綱（outline.md）

**輸入**：審核過的 themes.md + book-config.yaml（這時可填入正式書名）

**動作**：

1. 確定書名（給 3 個候選讓使用者選）
2. 規劃章節結構：序章 + N 個主章 + 結語（建議 8–12 章）
3. 每章寫：
   - 章節標題
   - 章節核心問題（一句話）
   - 章節主要論點 3–5 條
   - 預計用到的素材檔案
   - 預計頁數

**輸出格式**：

```markdown
# 書名候選
1. 《呼吸的解剖學》
2. 《從橫膈膜到地心引力》
3. 《活的解剖學課》

# 章節大綱

## 序章：為什麼這本書
- 核心問題：傳統解剖學課為什麼讓人想睡？
- 論點：1) ... 2) ... 3) ...
- 素材：心得-2024-01-教學反思.md
- 預計頁數：8

## 第 1 章：呼吸不是換氣
- 核心問題：橫膈膜到底在做什麼？
- 論點：...
- 素材：呼吸營逐字稿.md, FB-橫膈膜貼文.md
- 預計頁數：18

## ...
```

**Stage 3 結束 → 停下來。** 對使用者說：

> 「章節大綱完成。請選定書名、確認章節順序與份量。確認後我會逐章寫稿，每章寫完都會回報。」

---

## Stage 4：逐章寫稿（chapters/）

這是最關鍵的階段。**每章獨立執行。**

**動作（每章重複）**：

1. 建立 `chapters/01-xxx.md`（NN 是章節編號）
2. 讀取：book-config.yaml + outline.md 對應章節 + 該章指定的素材檔案
3. 開始寫稿。寫稿規則：
   - 章節開頭：用素材中的具體故事、案例、學員問題開場（不要抽象）
   - 章節主體：把素材中的觀點重組為流暢敘事，不是逐字摘抄
   - 章節結尾：take-home message（3–5 條 bullet）+ 下一章預告
   - 引用：學員的話、文獻的話用引號標出，註明出處
   - 圖表：用 `[圖 1-1：橫膈膜結構，待補]` 標註
4. 寫完一章後，**停下來給使用者審核**。不要連續寫第二章。

**每章長度建議**：3000–6000 字（中文）

**寫完一章後對使用者說**：

> 「第 N 章「XXX」寫完，共 XXXX 字。請審核。確認後我會繼續第 N+1 章；如需調整語氣或內容，告訴我具體要改的方向。」

---

## Stage 5：整書潤飾（book.md）

**輸入**：所有 chapters/NN-xxx.md

**動作**：

1. 把所有章節合併成 book.md
2. 寫序（為什麼寫這本書、給誰看、怎麼讀）
3. 寫結語（讀完之後可以做什麼）
4. 全書通讀：
   - 統一術語（用 book-config 的 terminology）
   - 移除 forbidden_phrases
   - 修正章節間的重複內容
   - 補上目錄
5. 加上版權頁、致謝、參考文獻

**輸出**：完整的 book.md

**Stage 5 結束 → 停下來。** 對使用者說：

> 「整書潤飾完成，共 X 章 / 約 X 萬字 / 預估 X 頁。請通讀 book.md，確認沒問題後進入 Stage 6 輸出 PDF。」

---

## Stage 6：PDF 輸出

**動作**：

1. 呼叫 `pdf` skill（讀取 `/mnt/skills/public/pdf/SKILL.md`）
2. 把 book.md 轉成 PDF，套用：
   - 中文字體（思源宋體 / 思源黑體）
   - 章節分頁
   - 目錄自動生成
   - 頁碼
   - 封面（可選：用 boneman-style skill 生成）
3. 輸出到 `output/書名_v1.pdf`

**完成 → 對使用者說**：

> 「《書名》v1 已輸出至 output/書名_v1.pdf。共 X 頁 / X 萬字 / X 章。
> 後續可考慮：(a) 找人試讀回饋 (b) 翻譯成英文版 (c) 上架電子書平台。」

---

## 防呆規則

1. **絕對不要跳階段。** 即使使用者說「直接幫我寫完」，也要分階段卡點。
2. **每章獨立 context。** 寫完第 N 章後，下一章重新讀 book-config + outline，不依賴前一章的對話記憶。
3. **素材引用必須真實。** 不可以「為了補充」而捏造學員 Q&A 或案例。如果素材不夠，回報使用者，由他決定要補寫還是刪減。
4. **forbidden_phrases 嚴格檢查。** 每章寫完都要 grep 一次，有違反就改掉。
5. **語氣一致性。** 每章寫完，用 book-config.tone 自我檢查：「這段語氣符合設定嗎？」

---

## 與其他 skill 的協作

- **literature-organize**：如果素材包含 PDF 文獻，先用 literature-organize 整理成卡片
- **boneman-style**：書封與章節插圖的視覺風格
- **pdf**：Stage 6 的 PDF 輸出
- **token-saver**：長書寫作 context 容易爆，每章獨立 + checkpoint 是必要的
